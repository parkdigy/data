# npm 패키지 코딩 절차

이 저장소에서 기능, 공개 타입 또는 빌드·배포 설정을 변경할 때 사용한다. 먼저 [저장소 지침](../../../AGENTS.md), 관련 소스·테스트 및 필요한 경우 [프로젝트 구조](../../../docs/agents/project.md)를 확인한다.

1. `git status --short`로 기존 변경을 확인하고 요청에 관련된 현재 동작과 타입, 검증 방법을 파악한다.
2. 공개 기능을 변경할 때 `src/index.ts`의 이름 있는 내보내기와 기본 객체, 관련 선언과 호출자를 함께 확인한다. `copy`는 JSON 직렬화 기반이며 `lv`, `vl`, `makeConst`는 리터럴 타입 추론과 런타임 동작이 모두 공개 계약에 영향을 준다. 변경에 관련된 입력과 경계 조건을 실제 API 테스트로 검증한다.
3. 사용법이 바뀌면 README와 예제에 필요한 변경을 반영한다. 현재 예제는 별도 npm 프로젝트의 단순 콘솔 출력이며 설치된 패키지의 소비 검증을 대신하지 않는다.
4. `AGENTS.md`의 타입·lint·테스트 명령을 실행한다. 빌드 관련 변경은 빌드도 검증하되, Rollup이 Git 추적 중인 `dist/*`를 지우므로 먼저 기존 변경을 확인하고 보존한다. 배포 설정 변경은 패키지 목록과 설치 소비자의 `import`·`require`·타입 해석을 확인한다.
5. 실패를 코드 회귀, 기존 문제, 환경 오류로 구분해 기록한다. Watchman 오류 시 안내된 대체 검증의 결과를 표준 빌드 성공으로 표시하지 않는다. diff와 생성물, 기존 변경 보존 여부를 검토하고 결과와 미확인 사항을 한글로 보고한다.

여러 세션에 걸치거나 인계가 필요한 경우에만 [작업 기록 양식](templates/task.md)을 `_workspace/<작업명>/task.md`에 복사해 사용한다. 기존 기록을 덮어쓰지 않는다.
